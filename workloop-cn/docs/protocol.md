# Workloop 最小协议

## 目标

Workloop 只控制两件事：认知是否足够可靠，完成结论是否有真实证据。它不替代工程判断，也不为每种任务建立不同流程。

## 四个阶段与固定产物

| 阶段 | 产物 | 必须回答的问题 |
|---|---|---|
| 需求理解 | `spec.md` | 目标、非目标、事实、阻塞假设、最大风险和验收标准 |
| 计划与执行 | `plan.md` | 工作项、范围、依赖、验收映射、验证和证据索引；仅在存在共享边界时增加契约 |
| 独立验证 | `review.md` | 验收、计划、实现和证据是否语义一致，是否越界，最大风险是否真正被验证 |
| 失败学习 | `.workloop/memory.md` | 哪个触发条件可能重现，以及届时应执行什么预防检查 |

不要把原始日志、截图或测试报告粘贴到 `plan.md`。证据只记录稳定 ID、结果、观察时间、来源路径和覆盖的验收或契约 ID；需要时再读取原始来源。

## 最小状态机

```text
clarifying → specified → executing → reviewing → done
```

- `blocked` 暂停当前阶段。记录 `blocked_from` 和 `resume_when`，条件满足后返回原阶段。
- `cancelled` 是终态。
- 状态只存储在 `spec.md` 的前置元数据中。

## 一致性关系

完成前只检查六组可定位关系：

1. 意图 ↔ 验收标准；
2. 验收标准 ↔ 工作项；
3. 阻塞假设 ↔ 关闭证据；
4. 共享契约 ↔ 供给方和消费方工作项；
5. 验收标准及契约 ↔ 有效证据；
6. 失败原因 ↔ 可执行预防检查。

插件检查结构完整性；未参与实现的审查者判断实现行为是否真是用户所需。插件不能把某个字符串存在当成业务语义正确。

## 仅在需要时创建

- 没有共享边界，不创建契约。
- 没有真实失败或独立发现的缺陷，不新增错误记忆。
- 只有一个工作项且无需委派，不生成工作项投影。
- 需求没有量化目标，不创建质量指标。
- 一个干净上下文无法完成时拆分新的 Loop，不扩展状态机。

## Skill 与插件边界

`workloop-skills/` 定义理解、计划、执行、独立审查和失败学习方法，必须保持人可读、可独立使用，并按阶段加载。

`workloop-plugin/` 只固化机器能够可靠判断的规则：状态、必需区块、稳定 ID、验收覆盖、阻塞假设、契约双向引用、证据引用、工作项范围和审查结构。不得恢复完整知识状态、复杂 Schema、失败卡账本或旧控制快照。

## 语言规则

英文是唯一可执行主版本，因为解析键、状态值、命令接口和跨 Agent 交接需要一套稳定词汇。`workloop-cn/` 为所有人类可读内容提供同路径中文对照；运行时代码和插件发现不会加载本目录。
