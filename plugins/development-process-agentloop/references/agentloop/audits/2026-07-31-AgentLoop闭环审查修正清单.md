# AgentLoop 闭环审查修正清单

## 结论

以下清单以源码和可重复实验为准，替代外部审查中的绝对化表述。

## 确认缺陷

| 编号 | 缺陷 | 修复目标 |
|---|---|---|
| 018 | 分类触发的必填项没有结构化义务和转换门禁 | 新 Loop 记录分类依据与义务，需求确认前按主要类型检查 |
| 019 | 执行档位升级、`self_check` 降档主要依赖 Agent 自判 | 结构化资格项并在路由、转换时检查 |
| 020 | 非原型开发流程的流程特有 MUST 没有统一编码前门禁 | 用一个通用 assurance 产物承载路线特有输入、输出、检查、批准与恢复 |
| 021 | `files`、文件名和 `required_outputs` 的语义映射未在协议中完整定义 | Markdown、Schema、控制程序统一命名层级和映射 |
| 022 | 控制快照缺失时静默重建，可接受被篡改状态 | 缺失即失败；只能通过显式、可追溯恢复重建 |
| 023 | 人工 Gate 事件由 CLI 任意自报，无法证明来自宿主用户事件 | 限定 Gate 状态并明确宿主证明边界；默认拒绝未认证事件 |
| 024 | Gate subject digest 只写不查 | `validate` 和状态推进重新计算当前摘要，变更即令审批失效 |
| 025 | Hook 只覆盖部分写工具且放行控制目录 | Hook 改为提示与前置拦截；硬安全仍由每个控制命令入口负责 |
| 026 | Evidence `--result` 与实际执行结果脱节 | 参数与真实退出结果必须一致，`blocked` 不伪装成运行结果 |
| 027 | 非 UI flow 可以只凭退出码通过，没有断言报告 | `flow_id` 对所有执行器要求本次 nonce/commit 绑定且断言大于零的报告 |
| 028 | 项目运行时 Schema 可能滞后且没有升级入口 | 增加显式 runtime upgrade/check 命令，初始化继续覆盖同名文件 |

## 修正后的非缺陷或降级项

- `需求分类.md` 没有要求“缺陷修复必须提供复现路径”；正确缺陷是现有分类义务没有机器闭环。
- 缺陷修复定义已要求“确认过的预期”和规则依据；缺的是结构化检查，不是完全没有语义。
- 分类判断顺序提供了优先级，但复合意图仍需记录冲突消解依据。
- 不是“其余八个开发流程完全没有闭环”；它们共享 Git、状态和验证门禁，但路线特有的编码前 MUST 普遍没有机器闭环。
- 技术研究已有 `verifying → verified → done` 映射；无需另造状态。
- `copytree(..., dirs_exist_ok=True)` 会覆盖同名 Schema；问题是旧项目恢复时没有显式同步入口。
- 非 UI 命令由插件真实运行；缺陷是 flow 级语义可能只有退出码，没有断言和步骤覆盖。
- Hook 无法成为同一操作系统用户下的安全边界；扩展命令匹配只能减少误操作，不能替代控制入口校验。

## 不纳入本轮的错误修复建议

- 不新增“复现路径”字段来修复一条原文不存在的规则。
- 不为九条开发路线各造一套状态机和 Schema；使用统一 assurance 契约，路线只声明必要义务。
- 不把 `copytree` 改成另一种“强制覆盖”实现；保留标准库行为，补显式 upgrade。
- 不宣称本地 CLI 能独立证明人类身份；没有宿主签名/认证事件时保持 Gate 未通过。
