# 关键假设与决策依据未进入控制闭环

## 现象

Loop 保存分类、路由结果和一段自然语言理由，但不保存决定范围、验收和实现方向的关键假设，也不要求列出候选方案、选择证据和排除理由。

## 影响

Agent 可以把推测当事实直接进入开发；当结果偏离预期时，无法定位是哪项前提错误。流程选择容易退化为“先选熟悉流程，再补一段合理理由”。

## 根因

控制层主要验证状态和产物是否齐全，对推理输入只保留最终结论，没有为假设生命周期和决策证据建立结构化契约。

## 旧门禁为何没拦截

`routing.reason` 只要求非空，Schema 和控制程序都不检查前提是否已经验证，也不检查主流程是否对应最大风险。

## 修复

- `loop.yaml` 新增 `assumptions` 和 `decision_records`。
- 新增 `assumption`、`decision` 控制命令；确认或否定假设必须附证据。
- 路由必须声明 `risk_driver`，并按风险类别确定主流程。
- 影响路由、验收、实现或验证的未验证假设会阻止路由。

## 回归

- 无证据不能把假设标记为 confirmed/rejected。
- 未验证的阻塞假设会拒绝路由。
- 风险类别与主流程不匹配会拒绝路由。
- 决策记录必须至少包含两个候选，且选择必须属于候选集合。

## 预防规则

任何会改变范围、验收、实现或验证的推测都必须先成为有生命周期的假设；任何存在真实备选项的关键选择都必须记录证据和排除依据。
