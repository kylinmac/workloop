# 视觉通过掩盖业务未持久化

## 现象

按钮、Toast、弹窗关闭和页面跳转通过，但刷新或重新登录后数据丢失，仍被当成功能完成。

## 影响

高保真前端复刻被误判为生产可用业务系统。

## 根因

视觉保真与业务功能共用一个模糊的 UI passed 结果，交互没有 mutation、readback 和持久化断言。

## 旧门禁为何没拦截

自报 interaction 名称和 passed JSON 即可满足覆盖，没有执行完整业务旅程。

## 修复

拆分视觉 Gate 与业务 Gate；写操作必须验证请求、Repository/数据库变化、readback、刷新、重登、失败、权限、下游和审计。

## 回归

只修改前端本地状态的保存操作，即使视觉完全一致，也必须阻止 verified。

## 预防规则

视觉通过不能补偿业务失败；持久化写操作少一个必需断言即失败。
