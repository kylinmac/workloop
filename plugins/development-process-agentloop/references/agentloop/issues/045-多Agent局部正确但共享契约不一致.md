# 多 Agent 局部正确但共享契约不一致

## 症状

前端、后端或多个服务 Agent 各自完成任务，但接口字段、业务语义、状态、错误和验收理解不一致，形成“局部正确、整体错误”。

## 根因

现有 Flow 能生成 OpenAPI、数据模型和验收义务，却没有一份所有参与者共同确认、摘要冻结并由实现一致性 Evidence 覆盖的横向协作契约。

## 修复

增加可选但必须显式决定的 Contract Layer。required 时使用统一 `development-contract.yaml` 描述 API、数据语义、行为和验收场景；所有消费者确认同一摘要后才能编码。验证报告覆盖每个契约 ID 的提供方、消费方和语义一致性。

## 回归

覆盖未声明、参与者不完整、契约结构错误、验收映射错误、确认后篡改、实现路径缺失、检查覆盖不完整和合法协作闭环。
