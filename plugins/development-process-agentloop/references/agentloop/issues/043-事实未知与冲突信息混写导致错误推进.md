# 事实未知与冲突信息混写导致错误推进

## 症状

需求、代码、文档和运行结果中的信息被统一写进自然语言理由，无法区分已确认事实、尚未回答的问题和互相冲突的来源。Agent 可能挑选其中一个说法继续推进。

## 根因

控制模型只有假设和最终决策，没有独立知识状态；状态转换也不知道某个未知项或冲突会影响路由、验收、实现还是验证。

## 修复

- 新增 `knowledge_state.known/unknowns/conflicts` 和 `knowledge` 控制命令。
- 每项知识声明影响阶段、来源、责任人和更新时间。
- 未解决的阻塞未知项或冲突在对应路由与状态转换前拒绝推进。
- 解决未知项或冲突必须保存结论和证据。
- 阶段上下文只投影当前阶段相关的知识，避免重新膨胀。

## 回归

覆盖三类知识的创建与更新、无来源事实拒绝、无证据解决拒绝、跨类别重复 ID 拒绝、路由阻塞和阶段投影过滤。
