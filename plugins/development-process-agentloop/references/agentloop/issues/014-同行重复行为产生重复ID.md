# 同行重复行为产生重复 ID

## 现象

真实原型扫描得到 299 条行为但只有 237 个唯一 ID；同一行出现多个相同目标时生成相同 behavior_id，写入后才被 validate 拒绝。

## 影响

恢复后的 product-prototype 无法建立行为清单，也不能合法进入矩阵重建。

## 根因

ID 只包含文件、行号、行为类型和目标，没有包含同行匹配位置。

## 旧门禁为何没拦截

回归原型每行只有一个事件或导航；`prototype-scan` 写入前也没有执行 ID 唯一性自检。

## 修复

ID 加入一基源码列号，inventory 显式记录 `source_column`；扫描命令在写文件和状态前校验全部 ID 唯一。

## 回归

同一行包含三个相同 href 或事件目标时，必须产生三个不同 ID，且清单通过唯一性校验。

## 预防规则

从源码位置派生的稳定 ID 必须覆盖行与列，并在持久化前检查唯一性。
