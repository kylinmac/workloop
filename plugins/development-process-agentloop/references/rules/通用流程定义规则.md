# 通用流程定义规则

## 适用范围

本规则适用于需求确认流程、开发流程、测试验证流程以及未来新增的流程类型。

它只规定所有流程共同遵守的结构，不代替各阶段自己的专用规则。

所有流程先遵守[AgentLoop 设计原则](../agentloop/AgentLoop设计原则.md)。流程定义不仅描述理想步骤，还必须说明控制点、证据身份、失败退回和升级恢复。

## 核心规则

每个流程阶段都必须具备：

```text
明确输入
→ 可执行操作
→ 明确产物
→ 产物最低内容
→ 检查或验证方式
→ 阶段出口
→ 失败或不满足时的退回位置
→ 中断、重跑和旧版本升级后的恢复入口
```

只有“分析、设计、处理、测试”等抽象名称，没有明确产物和出口条件，不能作为正式流程阶段。

## 强制规则闭环

流程中的每条强制规则必须登记到以下控制闭环，允许合并记录在当前规范文件中：

| 项目 | 必须回答 |
|---|---|
| 独立依据 | 规则和验收来自哪个不由实现自报的事实源 |
| 结构表达 | 由哪个字段、Schema、契约或已确认产物表达 |
| 推进门禁 | 哪个 transition、Gate 或人工审批阻止违规推进 |
| 真实证据 | 由哪个可执行检查产生，绑定什么需求版本和提交 |
| 生命周期 | 新证据怎样替代旧证据，变化时哪些内容 stale/superseded |
| 恢复回归 | 失败、重跑、中断和旧版本升级怎样恢复并被测试 |

能自动检查却没有进入控制程序的“必须”尚未完成；确实不能自动检查时必须指定人工 Gate 和确认对象。

## 防止封闭自证

验收义务、实现清单和测试覆盖不能全部来自同一份由执行 Agent 填写的列表。流程必须至少保留一个独立基线，并检查：

```text
独立基线义务集合
== 实现映射集合
== 验证映射集合
== 当前 active Evidence 覆盖集合
```

允许偏差必须在实现和测试前明确记录依据，不能在失败后临时缩小基线。

## 产物规则

产物不等于文档。产物可以是：

- 一个被确认的流程状态
- 一段可执行代码或脚本
- 数据库结构或接口契约
- 测试代码和真实运行报告
- 原型、截图、日志或测量结果
- 确实需要长期保存的说明

产物必须：

- 有明确名称和保存位置
- 能被人和 AI 再次读取
- 标明所属需求或任务
- 标明草稿、待确认、已确认或已废弃状态
- 能追溯到上游输入
- 能被下游流程直接使用
- 标明适用的 `loop_id / requirement_version / scope`；运行证据还必须绑定 `flow/check`、测试提交和运行身份

聊天中的临时回答只有保存并确认后，才能成为正式产物。

## 最小产物原则

文件数量不是流程完整性的标准。

- 多个简单阶段可以记录在当前阶段的规范文件中；文件位置由产物与目录协议统一定义。
- 已有文件可以承载新信息时，直接更新，不新建重复文档。
- 能由代码、测试框架或工具自动生成的结果，不再人工抄写一份说明。
- 只有需要确认、交接、追溯或长期复用的信息才单独建文档。
- 简单流程不得为了套模板生成大量空泛文件。

默认最小闭环：

```text
一个流程定义
+ 一个实际执行产物
+ 一个真实结果
```

## 可执行优先

能够通过代码、脚本、测试、命令或自动化操作证明的结果，应优先产出可执行内容和运行证据。

说明文档不能代替真实执行。流程设计必须回答“由什么执行、如何判断、证据在哪里”。

## 版本控制与可追溯

任何会修改项目文件的流程，都必须遵守[Git 版本控制与可追溯规则](Git版本控制与可追溯规则.md)。

项目未由有效 Git 仓库管理时，必须先检查待提交文件、敏感内容和忽略规则，通过 `repository_bootstrap` Gate 后初始化仓库并建立初始基线提交。不得依赖 AI 记忆、聊天记录或重新生成内容作为回滚方式。

AgentLoop 产物的保存位置、命名和单一事实来源必须遵守[AgentLoop 产物与目录协议](../agentloop/产物与目录协议.md)。

## 产物等级

- 必需产物：缺少时不得进入下一阶段。
- 条件产物：满足触发条件时必须产生。
- 可选产物：不影响流程继续，不得被自动扩大为强制工作。

## 流程组合

流程可以组合，但必须明确：

- 主流程
- `supporting_flows`
- 各 `supporting_flow` 的触发条件
- 上下游交接产物
- 共用产物
- 最终出口由哪个流程决定

已有产物满足下游要求时直接复用，不重复生成内容相同的文档。

这里的 `supporting_flows` 是方法组合；只有写入 `loop.yaml.subflows` 的独立执行单元才称为子流程。

## 大流程拆分

一个流程能够在同一需求下独立开发和验证时，拆成 `loop.yaml` 中的子流程。

出现以下任一情况时，升级为独立子 Loop，而不是继续膨胀同一个 Loop：

- 可独立确认、交付或回滚
- 不同负责人、仓库、工作树或发布节奏
- 需要独立并行
- 恢复时无法只加载该单元的需求、开发记录和声明范围

每个子流程仍必须遵守输入、操作、产物、验证和出口规则。

复杂流程的主要额外产物是拆解清单和依赖关系，不是为复杂度增加更多阶段文档。拆解后的每个执行单元应复用同一个最小执行闭环。

## 完成条件

流程完成必须同时满足：

```text
必需阶段已执行
+ 条件阶段已按触发条件执行
+ 必需产物已产生
+ 产物检查通过
+ 未解决问题已关闭或明确记录
+ 强制规则已经形成控制闭环
+ 正常、失败、重跑、恢复和升级路径按风险完成回归
+ 最终结论和下一步明确
```
