# 代码流程验证

## 适用范围

后端、接口、领域、数据、迁移以及能够通过代码执行和 Assert 判断的端到端流程。

## 执行流程

```text
根据测试交接确定需要验证的业务流程
→ 按覆盖索引查找已有可复用测试流程定义和流程测试
    ├── 已存在
    │   → 确认预期保持不变还是按需求改变
    │   → 复用原测试；只更新明确改变的断言
    └── 不存在
        → 写可复用测试流程定义
        → 编写一个流程测试类
→ 每个关键分支写一个测试方法
→ 运行测试
→ Assert 响应、中间状态和最终结果
→ 保存测试框架报告
→ 通过，或修复后重跑
```

## 产物规则

```text
已有流程回归
→ 复用原测试流程定义和测试类
→ 只新增本次运行结果

新增独立流程
→ 新增测试流程定义、流程测试类和运行结果
```

### `.agentloop/flows/<flow_id>.yaml`

只有没有现有流程可以覆盖时才新增。定义必须包含 `covers` 索引。预期明确改变时，更新原定义中受影响的步骤，不复制一份回归定义。

```yaml
flow_id: refund-application
executor: code
steps:
  - action: 创建已支付订单
    expect: order.status == PAID
  - action: 提交退款
    expect: response.status == 201
  - action: 重复提交
    expect: refund.count == 1
checks: [response, state, database, idempotency]
```

### 流程测试类

已有测试类可以覆盖时直接复用。只有出现原测试无法表达的新独立流程时才新增。

```text
RefundApplicationFlowTest
├── should_complete_refund_application
├── should_reject_unpaid_order
└── should_not_duplicate_refund_when_retried
```

测试从真实服务入口或接口开始，连续执行到最终结果。必要时 Assert：

- 返回结果
- 数据库状态
- 领域状态
- 事件或消息
- 外部调用
- 重复、失败和回滚行为

### 运行证据

- 测试命令
- 测试框架原始报告
- Assert 失败和堆栈
- 必要日志、请求响应和数据查询

## 完成条件

流程的正常路径和关键失败路径均已真实运行，关键结果有 Assert，测试报告状态明确。
