# 命令与实验流程验证

## 适用范围

性能、安全、迁移命令、故障恢复、数据批处理和技术实验。

## 执行流程

```text
根据测试交接确定需要验证的命令或实验场景
→ 按覆盖索引查找已有可复用测试流程定义、脚本和阈值
    ├── 已存在
    │   → 确认环境、输入和预期是否改变
    │   → 复用原脚本和阈值
    └── 不存在
        → 定义可重复场景
        → 预先定义指标和阈值
        → 编写命令、脚本或实验程序
→ 固定环境和数据
→ 真实运行
→ 收集原始结果
→ 由代码 Assert 阈值
→ 保存报告
→ 通过，或调整后重跑
```

## 产物规则

```text
已有场景回归
→ 复用原测试流程定义、脚本和阈值
→ 只新增本次原始结果和判定

新增独立场景
→ 新增测试流程定义、可执行程序和运行证据
```

### `.agentloop/flows/<flow_id>.yaml`

只有没有现有场景可以覆盖时才新增。定义必须包含 `covers` 索引。需求明确改变指标时，在原定义中更新阈值并保留变更依据。

```yaml
flow_id: refund-api-load
executor: command
command: ./run-load-test.sh
assert:
  p95_ms: "<= 300"
  error_rate: "< 0.001"
checks: [performance]
```

### 可执行程序

已有程序可以覆盖时直接复用。新增程序可以是：

- 命令脚本
- 性能场景文件
- 迁移和回滚脚本
- 故障注入脚本
- 实验或基准测试程序

必须可重复运行，并明确环境、输入、清理和停止条件。

### 运行证据

- 真实命令和退出状态
- 原始指标、日志或数据差异
- 阈值 Assert 结果
- 环境、版本、数据规模和持续时间

## 完成条件

场景可重复执行，结论由预先定义的阈值和真实结果产生，而不是由 AI 阅读报告后主观判断。
