# 修复 Codex 环境下不可达的 HMAC Gate

## 原始需求与事实

- 用户要求将 AgentLoop 改为当前 Codex 桌面端可以支持的确认方式。
- `host_hmac` 于提交 `9ab804d9df33a7a530b8bebe382e820a69a67449` 引入，提交时间为 2026-07-31 15:08:50 +08:00。
- 当前 Codex 插件没有可向本地脚本提供 `AGENTLOOP_GATE_EVENT_SECRET` 和签名审批事件的宿主适配器，默认 `host_hmac` 会使普通需求确认和完成验收不可达。

## 用户、场景与目标

- 用户在 Codex 对话中明确批准需求或验收后，普通 Gate 应可通过可追溯的本地确认继续。
- 插件不得提示用户点击一个实际不存在的认证确认入口。
- 保留 `host_hmac` 作为未来宿主适配器或显式高强度环境的可选模式。

## 范围、非目标、规则与约束

- 修改项目配置 Schema、默认示例、CLI Gate/doctor/配置命令、技能与协议说明、回归测试和问题档案。
- 新项目默认 `local_attestation`；旧项目不静默覆盖用户配置，通过受控命令显式切换。
- `destructive_action` 默认仍使用 `host_hmac`，普通确认的兼容降级不得降低破坏性操作门禁。
- 非目标：伪造宿主签名或实现一个并不存在的 Codex 私有审批 API。

## 验收标准

- AC-GATE-01：新项目默认使用 `local_attestation`，对话中的明确批准可被记录为带来源、事件 ID、需求版本和产物摘要的 Gate 事件，无需 HMAC。
- AC-GATE-02：`host_hmac` 仍可显式启用，缺少宿主密钥或签名错误时必须失败关闭。
- AC-GATE-03：`destructive_action` 默认单独使用 `host_hmac`，不能因普通 Gate 改为本地确认而降级。
- AC-GATE-04：现有项目可通过控制命令切换普通 Gate 认证方式，`doctor` 能指出不可用的 `host_hmac` 配置和恢复命令。
- AC-GATE-05：文档明确区分可追溯本地确认与密码学宿主认证，并新增问题档案与负向回归。

## 分类与复杂度

- 类型：内部改进。
- 档位：standard；单插件内的配置、控制程序、文档和回归联动修改，无独立交付单元。
