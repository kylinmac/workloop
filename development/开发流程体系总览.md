# 开发流程体系总览

## 总览职责

本总览是 Agent 在需求达到可开发状态后的选择器和路由入口，只负责回答：

```text
当前需求最容易在哪个地方跑偏
→ 当前工作是单流程、复合子流程还是父子 Loop
→ 选择哪个主开发流程
→ 是否需要组合其他流程
→ 将全部验收义务映射到实现承载、推进门禁和验证方式
→ 进入对应详细流程执行
```

具体约束遵循[开发流程定义规则](开发流程定义规则.md)，本总览不重复规定产物格式。

## 与需求分类的边界

```text
需求分类
→ 判断是什么性质的变化
→ 从 0、新增、修改、缺陷、内部改进、迁移升级、下线删除或技术研究
→ 同时携带 UI、流程状态、数据、外部集成、安全、性能、兼容和技术不确定性等标签

开发流程选择
→ 判断编码前最大的风险和不确定性在哪里
→ 选择需要先补齐原型、流程、契约、模型、架构、根因或实验中的哪一项
```

需求分类是本总览的输入，不直接等同于开发流程。

`trivial / standard / composite` 是执行复杂度模式，也不等同于开发流程。同一个“修改现有行为”既可能走 trivial + 快速变更，也可能走 composite + 业务流程驱动。

## Agent 选择流程

先读取已确认的需求、验收标准、需求分类、原型和现有代码。

统一按以下优先级判断；前面的特殊风险优先，`快速变更` 只在其他风险均未触发后使用：

```text
已确认缺陷且需要定位共同根因
→ 根因驱动修复流程

存在迁移、兼容窗口或回滚问题
→ 迁移与兼容驱动流程

关键技术能否成立缺少运行证据
→ 技术验证驱动流程

系统边界、模块关系或非功能指标是核心
→ 架构驱动流程

页面状态、交互方式或用户路径最不确定
→ 产品原型驱动流程

角色、步骤、状态、异常或补偿最复杂
→ 业务流程驱动流程

数据结构、接口契约或系统集成是核心
→ 数据与契约驱动流程

业务概念、规则和不变量最复杂
→ 领域模型驱动流程

以上均未触发，且改动范围小、实现路径明确、影响可控
→ 快速变更流程
```

从零开始不自动等于架构驱动。只有系统边界和整体结构是当前主要问题时才选择架构驱动；具体功能仍进入对应的开发切片。

## 主流程与组合

一个开发切片默认只选择一个主开发流程。

执行中出现其他问题时，只补充对应流程要求的产物，不重新走一套完整流程：

```text
原型流程中发现复杂状态
→ 补充业务流程和状态规则

业务流程中需要新增表和接口
→ 补充数据模型、表结构和接口契约

架构流程中的具体页面功能
→ 将产品原型驱动流程作为 supporting_flow 组合
```

已有产物能够满足需要时直接复用或补充。

同一需求中的多个可独立开发验证单元写入 `loop.yaml.subflows`。可独立确认、交付、回滚、并行，或恢复时无法只加载该单元的需求、开发记录和声明范围时，升级为父子 Loop。不同子流程可交错开发和测试，父状态按 AgentLoop 状态机聚合。

## 统一开发闭环

```text
选择主流程
→ 拆出可独立完成的开发切片
→ 按主流程补齐必要的编码前产物
→ 建立 assurance mapping：
    独立验收义务 → 实现承载 → Schema/契约 → transition/Gate → 验证 Flow
→ 编码前确认
→ 编写代码
→ 编译、静态检查和必要单元测试
→ 按验证策略分支
    ├── self_check → 记录实际结果 → verified
    └── targeted / flow → 形成测试交接 → ready_for_verification
→ 复合 Loop 按需执行 integration_verification
```

开发流程负责编码前准备、代码实现和开发自检；`self_check` 直接形成验收结论，`targeted/flow` 由[测试验证流程体系总览](../verification/测试验证流程体系总览.md)形成测试证据。

`assurance mapping` 不要求额外文件：trivial 合并在 `work.md`，standard 写入 `development.md`，结构化流程可直接使用原型矩阵、OpenAPI、状态表或其他主流程产物。关键是每个 acceptance_id 都有且只有明确承载，不能让实现清单成为验收基线。

进入具体流程后，Agent 必须按其中的“阶段—操作—明确产出—检查与出口”执行。说明和引用更新在 `development.md`；`trivial` 模式更新在 `work.md`。原型、契约、数据库脚本、代码、测试和工具结果保留为各自的实际文件，不为每个阶段另建说明文档。

## 选择检查

选择完成后，Agent 只需确认：

- 主流程对应当前最大的风险或不确定性
- 未触发的设计产物没有被强制生成
- 复杂需求已拆成可独立完成的开发切片
- 每个开发切片都有必要开发自检，以及与验证策略匹配的自检结论或测试交接
- 跨切片行为已经声明是否需要集成验证
- 每项验收已映射到独立基线、实现承载、推进门禁和可执行验证
- 新增协议、Schema 或 Gate 时已设计正常、失败、重跑、恢复和升级路径

事实不足时先补现状调查。多个主流程会导致明显不同的范围、产物或成本时，路由置信度设为 `low` 并执行项目审批 Gate，不用快速变更流程掩盖未决策问题。
