# 架构驱动流程

## 何时选择

系统边界、模块职责、数据所有权、关键调用链或非功能指标是当前最大的开发不确定性。

局部功能不选本流程；从零开始也只有整体结构需要先决定时才选择。

## 进入输入

- 已确认的系统目标、范围和验收标准
- 业务与技术约束
- 现有系统、部署和运行事实；改造现有系统时

## 编码前阶段与产出

| 阶段 | 操作 | 明确产出 | 检查与出口 |
|---|---|---|---|
| 1. 建立约束基线 | 调查现有系统、环境、外部依赖和硬约束 | `development.md` 中的现状、约束和不可改变行为 | 关键结论有现有实现或运行事实支持 |
| 2. 确定系统边界 | 明确系统负责和不负责什么 | 系统边界及外部关系 | 需求均有归属，范围外内容已排除 |
| 3. 划分模块职责 | 以最少模块分配职责和依赖 | 模块职责及依赖关系 | 职责无明显重叠，不存在循环依赖设计 |
| 4. 明确数据所有权 | 为关键数据确定唯一所有者和访问方式 | 数据所有权和跨边界访问规则 | 没有多个模块同时直接控制同一数据 |
| 5. 走通关键链路 | 描述关键请求、事件和失败处理 | 关键调用链和失败链路 | 正常与失败路径都能闭合 |
| 6. 定义非功能指标 | 将性能、安全、可用性要求改写为可测阈值 | 指标、负载条件和通过阈值 | 指标能够通过工具实际测量 |
| 7. 验证高风险假设 | 对未知技术点运行最小实验 | 实验脚本、原始结果和结论 | 关键架构不依赖未经验证的假设 |
| 8. 记录关键决策 | 仅记录重要且难以逆转的取舍 | 必要的架构决策记录 | 决策包含依据、取舍和撤销条件 |
| 9. 拆执行单元 | 拆成业务切片，判断保留为 `subflows` 还是升级为子 Loop，并选择各自开发流程 | `loop.yaml.subflows/child_loops`、依赖、范围、集成点和 `integration_verification` 决定 | 每个单元可独立恢复和验证；验收无遗漏；集成要求已显式决定 |

图、表和路线默认合并在 `development.md` 中，实验脚本和工具结果保留为实际产物。

复合或 epic 场景下，阶段 1—9 属于父 Loop 的总体准备。它们完成后父状态进入 `orchestrating`；实际编码不继续堆在父 `development.md` 中，而由各切片自己的主开发流程负责。

## 编码前确认

```text
边界、职责和数据所有权明确
+ 关键正常和失败链路闭合
+ 非功能指标可测
+ 高风险假设已有证据
+ 开发切片、分支合并路线和集成点明确
→ 允许各切片进入自己的开发流程
```

## 父 Loop 编排阶段与产出

| 阶段 | 操作 | 明确产出 | 检查与出口 |
|---|---|---|---|
| 10. 调度开发切片 | 每个切片进入自己的主开发流程和验证闭环 | 各 `subflow` 或子 Loop 的实际代码、检查点和验证结果 | 切片状态来自各自正式记录，父 Loop 不复制正文 |
| 11. 形成集成基线 | composite 和同仓库 epic 把验证过的 source commit 合并到父集成分支；跨仓库 epic 锁定各子 Loop 的已验证交付提交 | 同仓库的 `git.integration.merges/head_commit`，或跨仓库 epic 的 `child_deliveries` | 集成基线包含全部必需交付，冲突已退回责任单元 |
| 12. 集成验证交接 | 汇总精确集成基线、接口、数据、状态、指标和环境 | `integration_verification.handoff` | 同仓库 `code_commit` 等于 integration head；跨仓库 child delivery 提交均可定位 |
| 13. 聚合完成 | 等待切片、合并后检查和集成验证全部通过 | 父 Loop `verified` 或 `blocked` | 不以单个切片的 `ready_for_verification` 推进父状态 |

## 机器门禁与 standard 出口

assurance 必须包含 `boundaries`、`data-ownership` 和 `quality-thresholds`。Composite/epic 在父级进入 `orchestrating` 前检查；各子流程另按自己的 `scope_id/main_flow` 检查。

若调查确认只有一个不可独立拆分的交付单元，standard Loop 不进入父编排：完成上述 assurance 后直接 `development_preparing → developing`，实现完成后按普通测试交接进入验证。
