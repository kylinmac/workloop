# Workloop 最小认知协议 v0.1

## 1. 四项产物责任

`brief.json` 定义任务真相，`plan.json` 定义执行切片，`evidence.json` 定义结论依据，`failures.json` 定义失败后的认知修正。相同信息只允许有一个主归属，其他文件通过 ID 引用。

## 2. 认知项

认知项统一结构，不再拆分多套账本：

```json
{
  "id": "COG-001",
  "type": "assumption",
  "statement": "现有用户接口返回稳定的 userId",
  "status": "unverified",
  "blocks": ["executing"],
  "evidence_ids": []
}
```

`type` 只能是 `fact`、`assumption`、`unknown`、`conflict`、`decision`。事实必须有来源；已确认、已拒绝或已解决的非事实认知必须有证据；决策还必须记录候选项、选择项和依据。

## 3. 风险不是流程分支

风险记录产生义务：

- 关键未知产生认知验证义务；
- 共享 API、数据、行为或验收边界产生契约义务；
- 数据迁移、权限、资金和生产变更产生强化证据义务；
- 性能目标产生可量化验证义务；
- 执行失败产生错误记忆义务。

风险不会创建另一套状态机。

## 4. 工作包

工作包必须可以独立投影，至少声明：范围、依赖、输入引用、输出、验收引用和验证方法。工作包不能通过复制完整需求来获得上下文，只能引用当前需要的认知项、验收项和契约项。

## 5. 六组一致性关系

1. 目标与验收条件一致；
2. 验收条件被工作包覆盖；
3. 阻塞性认知在对应状态前有有效证据；
4. 共享契约被提供方和消费方实现与验证；
5. 完成结论被当前有效 Evidence 覆盖；
6. 失败原因对应认知修正，预防措施有通过的复验证据。

校验按目标状态执行，不在每一步扫描所有关系。

## 6. 完成定义

只有同时满足以下条件才可进入 `done`：

- 所有验收项存在 active、passed 的 Evidence；
- 所有阻塞 `done` 的认知项已经解决；
- 所有共享契约项具有 active、passed 的一致性 Evidence；
- 每条 failed Evidence 都存在 Failure Card；
- 每条 Failure Card 的预防措施已经通过复验；
- 所有工作包均为 done。
